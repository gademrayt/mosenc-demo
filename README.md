# Mosenc — рабочий план

Открой `index.html` двойным щелчком. Интернет, установка и сервер для плана не нужны.

## Файлы
- `index.html` — полный план с галочками, заметками, источниками и готовыми запросами помощи.
- `overview.html` — отдельное предложение для шефа, без личных отметок и путей компьютера. Не утверждает, что сайт уже готов.
- `PROJECT_CONTEXT.md` — границы нового проекта для продолжения с Hermes/Codex/Antigravity.
- `src/plan.json` — редактируемые инструкции; стабильные M/X ID не менять при обновлениях.
- `src/style.css`, `src/state.js`, `src/app.js` — исходники интерфейса.
- `build.py` — собирает оба автономных HTML (Python, только стандартная библиотека).
- `tests/` — воспроизводимые проверки. `qa/` — локальные тестовые изображения/PDF, не пользовательский прогресс.

## Отметки — важно
Галочки означают твою собственную отметку после проверки. Это не автоматический аудит сайта и не отметки Antigravity.

Они сохраняются в localStorage текущего браузера, а НЕ внутри HTML-файла. Очистка данных браузера, другой браузер/профиль, перенос файла или переход на другой URL могут дать пустой журнал. В конце сессии нажимай «Экспорт отметок». Для другого устройства: открой план и выбери «Загрузить отметки». Существующие записи заменяются только после подтверждения. Не открывай параллельно несколько редактируемых вкладок.

Экспорт содержит личные заметки. Храни его приватно; не пиши туда пароли и данные клиентов. Автоматической синхронизации с Git, GitHub, Mastery, Obsidian или другим компьютером НЕТ.

Для печати используй кнопку «Печать / PDF»: инструкции раскроются, фильтр временно отключится, после печати рабочий вид восстановится. Печатный полный план длинный; для встречи удобнее `overview.html`.

## Как работать
Один незавершённый шаг → действие в WordPress → проверка → заметка → галочка → экспорт.

Первый этап — определить чистую изолированную локальную площадку. В рамках создания плана WordPress, Docker, старые проекты, DNS и почта не изменялись. Никакая новая WordPress-установка ещё не создана.

## Git и публикация
Исходники готовы к версионированию, `.gitignore` добавлен. Git-репозиторий, remote и публикация сейчас НЕ создавались. GitHub/Vercel оставлены отдельными необязательными шагами X02/X03.

Перед первым коммитом согласуй границы репозитория и проверь состав. Сохранять можно только безопасные исходники/документы. SQL, wp-config.php, дампы, заявки, секреты и личные JSON-экспорты не должны попасть в историю. Для WordPress Git не заменяет резервные копии БД и uploads.

Текущий index.html включает внутренние рабочие пути и справочные материалы. Не публикуй всю папку автоматически. Для согласованного внешнего показа используй отдельно проверенный `overview.html`. Vercel может размещать статический HTML; обычный WordPress с PHP/БД требует подходящего хостинга.

## Разработка самого плана (не обязательна для пользователя)
```sh
python build.py
node --test tests/state.test.cjs
uv run --with playwright python tests/browser_test.py
uv run --with playwright python tests/qa.py
```
Для браузерных тестов нужен установленный Chromium Playwright. Скрипты используют существующий Chromium в `~/.cache/ms-playwright/`. Тесты работают в отдельных профилях и не меняют твои отметки.

Не запускай скрипты из других проектов ради этого плана. Прочитанные старые команды и порты — история, не инструкции к выполнению.
