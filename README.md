# Mosenc — рабочий план

**Текущая реализация с 16.09.2026:** основной WordPress — http://localhost:8100/, где успешно импортирован Kadence Starter Template **Coffee Shop** с Kadence Blocks и WooCommerce. 8101 сохранён как резерв и референс. Это смена визуальной основы, а не обнуление прогресса. Задачи ST01–ST05 и передача Antigravity находятся в начале HERMES_PLAN.md; старые порты и ручные шаги ниже — история.

**Актуально:** план и журнал ведёт Hermes в `HERMES_PLAN.md`. Пользователю не нужно открывать HTML, ставить галочки или экспортировать прогресс. Инструкции об HTML ниже сохранены только как справка к прежнему инструменту.

Открой `plan.html` двойным щелчком для учебного блокнота, `index.html` — для статического прототипа сайта. Интернет, установка и сервер для плана не нужны. Актуальная карта проектов, сайтов и проверенного состояния — в `PROJECT_CONTEXT.md` (сверка 2026-09-14).

## Файлы
- `plan.html` — полный план с галочками, заметками, источниками и готовыми запросами помощи.
- `index.html` и связанные страницы — статический прототип Mosenc; это не текущая WordPress-сборка на `http://localhost:8108/`.
- `overview.html` — отдельное предложение для шефа, без личных отметок и путей компьютера. Не утверждает, что сайт уже готов.
- `PROJECT_CONTEXT.md` — границы нового проекта для продолжения с Hermes/Codex/Antigravity.
- `src/plan.json` — редактируемые инструкции; стабильные M/X ID не менять при обновлениях.
- `src/style.css`, `src/state.js`, `src/app.js` — исходники интерфейса.
- `build.py` — собирает оба автономных HTML (Python, только стандартная библиотека).
- `tests/` — воспроизводимые проверки. `qa/` — локальные тестовые изображения/PDF, не пользовательский прогресс.

## Отметки — важно
Галочки означают твою собственную отметку после проверки. Это не автоматический аудит сайта и не отметки Antigravity.

Они сохраняются в localStorage текущего браузера, а НЕ внутри HTML-файла. Очистка данных браузера, другой браузер/профиль, перенос файла или переход на другой URL могут дать пустой журнал. В конце сессии нажимай «Экспорт отметок». Для другого устройства: открой план и выбери «Загрузить отметки». Существующие записи заменяются только после подтверждения. Не открывай параллельно несколько редактируемых вкладок.

Экспорт содержит личные заметки. Храни его приватно; не пиши туда пароли и данные клиентов. Автоматической синхронизации с Git, GitHub, Mastery, Obsidian или другим компьютером НЕТ.

Для печати используй кнопку «Печать / PDF»: инструкции раскроются, фильтр временно отключится, после печати рабочий вид восстановится. Печатный полный план длинный; для встречи удобнее `overview.html`.

## Как работать
Один незавершённый шаг → действие в WordPress → проверка → заметка → галочка → экспорт.

Первый этап актуального плана — проверить существующую локальную площадку `http://localhost:8108/`, не устанавливать её заново. Наличие WordPress не является автоматическим зачётом: изоляция, копии и сохранение требуют подтверждения. Обнаруженное различие pretty REST и query REST — технический пункт M02.

## Git и публикация
Локальный Git-репозиторий и история уже существуют. Есть конфигурация публикации; remote и фактическое внешнее размещение в сверке 2026-09-14 не проверялись. GitHub/Vercel в исходном плане описаны отдельными необязательными шагами X02/X03; наличие конфигурации не означает разрешение на новую публикацию.

Перед коммитом согласуй действие и проверь состав. Сохранять можно только безопасные исходники/документы. SQL, wp-config.php, дампы, заявки, секреты и личные JSON-экспорты не должны попасть в историю. Для WordPress Git не заменяет резервные копии БД и uploads.

Учебный `plan.html` включает внутренние рабочие пути и справочные материалы, а прототип ссылается на него. Не публикуй всю папку автоматически. Для согласованного внешнего показа используй отдельно проверенный `overview.html`. Vercel может размещать статический HTML; обычный WordPress с PHP/БД требует подходящего хостинга.

## Разработка самого плана (не обязательна для пользователя)
```sh
python build.py
node --test tests/state.test.cjs
uv run --with playwright python tests/browser_test.py
uv run --with playwright python tests/qa.py
```
Для браузерных тестов нужен установленный Chromium Playwright. Скрипты используют существующий Chromium в `~/.cache/ms-playwright/`. Тесты работают в отдельных профилях и не меняют твои отметки.

Не запускай скрипты из других проектов ради этого плана. Прочитанные старые команды и порты — история, не инструкции к выполнению.
